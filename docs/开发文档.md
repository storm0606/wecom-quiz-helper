## 1. 项目概述

### 1.1 定位

面向企业微信（WeCom / 企业微信 App）内答题考试场景的辅助工具：
答题过程中，App 通过**悬浮窗实时显示当前题目的正确答案**，用户**人工点选**作答。

> 注意：本应用只做"读题 → 查题库 → 显示答案"，不做自动点击。

### 1.2 目标用户与场景

- 用户：参加企业微信在线考试（单选题 / 多选题 / 判断题 / 简答题）的考生；
- 场景：考试答题页（含 H5 页面）停留在屏幕上，悬浮窗跟随显示答案；
- 题库：用户自备 Excel / Word 题库，导入 App。

### 1.3 版本管理规则（强制）

> 本规则为项目铁律，任何开发、修改、升级都必须遵守：

| 变更类型 | 版本号规则 | 示例 |
|---|---|---|
| 初始版本 | 1.0 | v1.0 |
| 小版本（功能增改、缺陷修复、优化） | **+0.1** | v1.0 → v1.1 → v1.2 → v1.9 |
| 大版本（架构重构、重大功能、不兼容变更） | **+1** | v1.9 → v2.0 → v3.0 |

- 每次交付/发布必须记录到本文件的"版本记录"章节（第 7 节）；
- 版本号以 `v主.次` 形式标注，禁止跳号。

### 1.4 技术栈

| 层 | 技术 |

### 2.2 题库导入需求（重要）

**2.2.1 支持的文件格式**

| 格式 | 解析方式 | 状态 |
|---|---|---|
| .xlsx | OOXML（zip + sharedStrings） | 原型已验证 ✅ |
| .xls | OLE2 + BIFF8 二进制 | 原型已验证 ✅ |
| .docx（表格题库） | word/document.xml 表格 | 原型已验证 ✅ |
| .csv | 标准 CSV（处理引号/逗号/换行） | 原型已验证 ✅ |

**2.2.2 表头识别与手动列映射**

- **多数题库首行包含关键词**：`题目类型`、`题目标题`、`题目答案`、`选项A`、`选项B`…（已有别名库自动识别，如 `题目类型→题型`、`题目标题→题目`、`题目答案→答案`）；
- **也有题库首行没有表头**（如 `题库1.xlsx`：`序号 | 题目 | 选项 | 答案` 四列直出数据）→
  **App 导入流程中必须提供"手动指定列映射"界面**：预览前几行，用户为每列选择角色
  （题目 / 题型 / 选项 / 选项A-D / 答案 / 序号 / 忽略）；
- 无表头时提供常见布局自动猜测（4 列 → `序号|题目|选项|答案`，3 列 → `题目|选项|答案`，8 列 → 标准布局），猜测失败则提示手动映射。

**2.2.3 答案格式兼容（关键）**

- 常规：`A`、`B`、`C`、`D`、`ABCD`、`正确`、`错误`、文本（简答）；
- **多选题答案可能写成 `A|B|C|D|`（带竖线分隔，末尾可能带 `|`）→ 归一化为 `ABCD`**；
  题库中以字母串存储答案（如 `ABCD`），**显示时转为选项文字**（见 §2.5 显示规则）；
- 判断题答案可能存字母（如 `A`，含义 = 选项 A 的内容"正确"）→ 通过题库选项翻译成文字。

**2.2.4 选项存放形式**

- 独立列：`选项A`、`选项B`、`选项C`、`选项D`…；
- 单列分隔：`A、正线 |B、停车场 |C、车辆段 |`（用 `|` 分隔，选项带字母前缀）→ 自动拆分；
- 选项文字可能带 `A、` / `A.` 前缀 → 自动剥离。

**2.2.5 无题型列时的自动推断**

| 特征 | 推断题型 |
|---|---|
| 有 4 个选项、答案为单个字母 | 单选 |
| 答案含多个字母（如 `AB`） | 多选 |
| 恰好 2 个选项且为"正确/错误（对/错）" | 判断 |
| 无选项、答案为文字 | 简答 |

### 2.3 实时识别需求（无障碍读屏）

- 通过 **AccessibilityService** 监听企业微信（包名 `com.tencent.wework`）答题页；
- 后台静默读取，**无需退出企业微信、无需截图权限、无需 OCR**；
- 已用真实控件树验证结构（详见 §5.1 与 §4.4）。

### 2.4 悬浮窗需求

- 申请 `SYSTEM_ALERT_WINDOW` 权限；
- 半透明小窗显示答案，支持拖动/缩放/收起；
- 未命中题库时明确提示，不误导。

### 2.5 显示规则

| 题型 | v1.0 显示（答案内容） | 示例 |
|---|---|---|
| 单选 | 答案选项的文字 | `对向道岔` |
| 多选 | 答案选项的文字 | `1.预防为主 2.防消结合` |
| 判断 | 正确 / 错误 | `正确` |
| 简答 | 题库答案文字 | `大运量、准点…` |
| 未命中 | 明确提示 | `未命中题库` |

### 3.1 Android 端总体架构

```

│  └─ 悬浮窗服务：显示答案 / 状态提示            │

```

## 4. 关键设计

### 4.1 文本归一化（`normalize`）

匹配前统一文本，消除题库与屏幕文本的格式差异：

1. NFKC 统一兼容字符（全角字母/数字 → 半角）；
2. 全角标点转半角（`，。、；：？！（）` 等）；
3. 删除所有空白（含换行，题干跨行也能匹配）；
4. 删除所有标点；转小写。

> 效果示例：题库 `“三权移交”是指…什么权？` 与屏幕 `三权移交是指…什么权?` 归一化后完全一致。

### 4.2 题干匹配（`matcher`）

三级匹配，按顺序：

1. **精确**：归一化题干哈希直查（覆盖绝大多数场景，O(1)）；
2. **包含**：屏幕文本可能是题干+选项混在一起的大文本块 → 归一化题库题干包含于屏幕文本；
3. **模糊**：编辑距离相似度（阈值 0.78）+ 长度粗筛，容忍个别字差异/OCR 噪声。

歧义处理：命中多道题干相似但答案不同的题 → 全部列出并提示"有歧义，请人工判断"。

**匹配题库范围（当前实现）**：只从**最新导入的题库**（`banks` 按 createdAt DESC 取第一个）中查找，其它题库不参与匹配；最新题库没有该题 → 未命中（即使旧题库里有）。
> 待用户决策的改进方向（v1.2 候选）：
> - 方案 A：**合并所有题库**查找（最新优先，旧题库兜底，命中率最高；跨库同题不同答案时提示歧义）；
> - 方案 B：**手动指定当前题库**（题库管理加"设为当前"，可控性最强）。

### 4.3 答案生成（v1 / v2）

- **v1（当前/首发）**：只显示答案内容，不匹配屏幕 ABCD 位置；
  - 单选 → 答案选项文字；多选 → 答案选项文字（自动编号 `1.` `2.` …，选项本身带数字则不再加）；
    判断 → 正确/错误；简答 → 答案文字。
- **v2（预留）**：读取屏幕选项文字，按内容定位实际字母，选项随机打乱也准；
  - 已知限制：真实控件树中**多选题的 B/C/D 字母节点缺失**（只有 A 有字母），
    v2 需要按 y 坐标顺序推断字母（已记录，见 §5.1 第 4 条）。

### 4.4 屏幕题目提取规则（`dump_reader`，已用真实数据定稿）

企业微信答题页控件树（包名 `com.tencent.wework`）已确认结构：

1. **选项是分离的两个节点**：字母节点（`A`）与文字节点（`顺向道岔`）在同一行，
   用 **y 坐标中心对齐**配对（误差 ≤3px）；
2. **题号行出现两次**：顶部悬浮题号 + 正文题号 → 去重（中间无实质内容则跳过）；
3. **题号行两种格式**：
   - 合并式：`第18题(2.00 分)`（单选页）；
   - 拆分式：`第26题` + `(2.00 分)` 两个节点（判断/多选页）→ 分值节点跳过；
4. **多选题 B/C/D 字母不出现在控件树**（v2 需按 y 顺序推断）；
5. **答完的题才显示"正确答案：X"**，正式作答时不存在 → 必须靠题库匹配；
   该行仅用于开发期交叉校验（`verify_ground_truth`）；
6. 页面顶部考试标题/及格线/进度（如 18/50）在题号行之前，忽略。

### 4.5 题库存储（SQLite / Room）

```sql
CREATE TABLE questions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    bank_id INTEGER NOT NULL,        -- 所属题库
    seq TEXT,                        -- 原序号
    qtype TEXT NOT NULL,             -- 单选/多选/判断/简答
    stem TEXT NOT NULL,              -- 题干（原文）
    stem_norm TEXT NOT NULL,         -- 归一化题干（建索引，精确匹配）
    option_a TEXT, option_b TEXT, option_c TEXT, option_d TEXT, option_e TEXT, option_f TEXT,
    answer TEXT NOT NULL             -- 归一化答案（A|B|C|D| → ABCD）
);
CREATE INDEX idx_stem_norm ON questions(stem_norm);
CREATE TABLE banks (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, file_path TEXT, created_at INTEGER);
```

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 企业微信风控/封号 | 自动答题行为被检测 | 只读屏不自动点击；建议小范围/内部使用；注意使用条款 |
| 企业微信改版 | 控件树结构变化导致读题失败 | 提取规则集中在 `dump_reader`，版本升级时回归验证；加日志便于快速适配 |
| 国产 ROM 杀后台 | 无障碍服务/悬浮窗失效 | 引导用户设置自启动 + 电池白名单 + 锁后台（首次使用引导页） |
| 题库格式千差万别 | 解析失败 | 手动列映射兜底 + 导入预览 + 明确错误提示 |
| 题干相似题答案不同 | 匹配歧义 | 全部候选列出，提示人工判断 |
| Android 14+ 权限收紧 | 无障碍/悬浮窗受限 | 严格走官方授权流程；分机型适配 |

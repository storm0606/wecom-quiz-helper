## 3. 版本验收标准

每个版本发布前必须满足：

- [ ] `selftest` 对应场景全绿（原型侧保持同步回归）
- [ ] 3 份真实 dump（单选/判断/多选）全链路通过
- [ ] 至少 1 份真实题库导入成功（含手动列映射路径）
- [ ] 真机：答题页停留时悬浮窗正确显示答案 ≥ 连续 10 题
- [ ] 未命中题库时给出明确提示（不得显示错误答案）
- [ ] 版本号已更新并记入《开发文档》版本记录

## 4. 测试计划

| 类型 | 内容 |
|---|---|
| 单元测试 | 归一化、匹配（exact/contain/fuzzy/歧义）、答案归一化（A\|B\|C\|D\|） |
| 解析测试 | 4 种格式 × {有表头/无表头/手动映射} × {单选/多选/判断/简答} |
| 控件树测试 | 3 份真实 dump 回归 + 结构变化告警 |
| 真机测试 | 主流 ROM 各一台；答题全过程 ≥ 30 分钟 |
| 性能测试 | 读屏延迟 < 1s；常驻内存 < 100MB；无明显耗电 |

---

## 5. 发布与版本管理流程

1. 开发 → 自测 → 真机验证 → 版本号升级（+0.1 或 +1）→ 记入版本记录 → 打包发布；
2. 每个版本保留发布包与对应测试报告；
3. 原型代码与 Android 代码**同步演进**：算法先在原型验证，再移植 Android；
4. 企业微信版本升级后，第一时间回归控件树提取（M3 的提取日志辅助定位）。
